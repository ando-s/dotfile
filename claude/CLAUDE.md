## Claudeセッションの管理

- マージリクエスト（MR）のレビュー依頼、ワークツリー作成依頼を受けた場合、セッション名は `Codereview MR !<MRのID>` というフォーマットで名前をつけてください。

## 回答の書き方（読みやすさ優先）

日本語の回答は、人間が一読で理解できることを最優先する。以下を守ること。

### ジャーゴンを使わない

- 業界内でしか通じないスラングや略語は使わない
- 専門用語が必要な場合は平易な言葉で言い換えるか説明を添える

### 分量・構造

- **結論を先に、数行で**。原則3〜5行で要点だけ返す。前置きや背景説明から始めない。
- **箇条書き中心**にまとめる。長い段落の連続を避け、視線移動を減らす。
- **全部を一度に出さない**。まず要点だけ返し、詳細は相手が求めたら掘り下げる。
- ただし**見逃すとリスクがある重要事項**（注意点・破壊的操作・前提崩れ等）は、聞かれなくても先に簡潔に伝える。

### 日本語とコードの分離

**この方針はチャット回答に限らず、計画ファイル・設計ドキュメント・MR 説明文・コミットメッセージなど、作成する日本語文章すべてに適用する。**

- **まず日本語の地の文で「何を・なぜ」を説明し、そのあとにコードブロックや箇条書きで識別子・コード・パスを示す**。地の文だけを読んで意味が通る状態を保つ。
- ファイルパス・コマンド・コード片・複数並ぶ識別子は、文中に埋め込まず必ず別行（コードブロック）に出す。
- 地の文に残してよいのは、文意に不可欠な 1〜2 語のクラス名・メソッド名程度に絞る。

フォーマット:
> 〇〇を、△△の理由でこう実装する（日本語の説明）
>
> ```ruby
> （実際のコード・識別子）
> ```

### 見出しの絵文字

見出しの先頭に絵文字を付け、重要度や注目度を一目で分かるようにする。

- 🔴 優先度が高い・緊急のセクション
- 👀 特に注目してほしいセクション
- ⚠️ 注意点・リスク・破壊的操作を含むセクション
- ✅ 完了・確認済み・結論のセクション

過剰に付けない。すべての見出しに付けると区別がつかなくなるため、強調したいセクションに絞る。

## 環境固有の前提

- 社内 GitLab は `gitlab.wwwave.info`。`glab` は `GITLAB_HOST=gitlab.wwwave.info glab ...` の形で実行する
- git commit の identity は `user.name=s-ando` / `user.email=s-ando@wwwave.jp` を使う
- Slack へのメッセージ送信は `~/.slack/send-ouen.sh` を使う（bot トークンは `~/.slack/shigoto-ouen-bot-token`）。Slack MCP は削除済みで、CLI のみ使用する

## 許可プロンプトを減らすコマンド選択

許可リストに載りやすい・自動許可済みのコマンドを優先し、不要な許可プロンプトを減らす。

- データの集計・フィルタリング・JSON処理は `python3` より `jq` + シェルコマンドを優先する
  - `jq` は自動許可済みのためプロンプトが出ない
  - `python3` はインタプリタなので許可リストにワイルドカードで載せられない（任意コード実行に等しい）
  - どうしても Python が必要な処理はスクリプトファイルに切り出し、そのファイルパス単位で許可する
