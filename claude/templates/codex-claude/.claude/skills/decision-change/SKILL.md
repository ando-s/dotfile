# 方針の変更

決まったことは `docs/product.md` にだけ書き、理由と履歴は `docs/decisions/` に残す。文書の外（画面の文言、構成図、AIへの指示）にも同じ決定が反映されているので、それらも一緒に揃える。ここを省くと、文書ごとに違うことが書かれた状態に戻ってしまう。

## 手順

1. **確かめる:** 何をどう変えるかを一文にする。曖昧なら本人に確認する。`docs/decisions/README.md` で関係する既存の決定を探す。
2. **決定記録を足す:** `docs/decisions/` に次の番号のファイルを作る（書き方は `docs/decisions/README.md`）。既存の決定を変える場合は、古いファイルの状態を「置き換え済み」にして新しい決定記録へのリンクを付け、古い本文は書き換えない。一覧の表にも行を足す。
3. **仕様を直す:** `docs/product.md` の該当箇所を新しい決定に合わせて書き換え、決定記録へのリンクを付ける。
4. **影響先を探して揃える:** 決定に関わる言葉で検索する。

   ```sh
   rg -n '検索語' --glob '!docs/worklog.md' --glob '!docs/archive/**' --glob '!docs/decisions/**' .
   ```

   | 見つかった場所 | 扱い |
   |---|---|
   | `app/`（画面の文言・AIへの指示） | 実装を変える依頼なら Codex に渡す。そうでなければ未対応として progress に書く |
   | 構成図 | 直して画像を作り直す |
   | `docs/proposals/` | product.md と食い違う記述を直すか、product.md へのリンクに置き換える |
   | `docs/research/` | 調査時点の記録なので書き換えない |
   | `docs/worklog.md`・`docs/archive/` | 履歴なので書き換えない |

5. **進捗を更新する:** `docs/progress.md` に、残った作業（実装・デプロイ・確認）を書く。
6. **検査する:** `python3 scripts/check_docs.py` を実行し、リンク切れがないことを確かめる。

## 報告

本人には次を短く伝える：足した決定記録、直した文書、直したコード（あれば）、まだ直していない影響先。
