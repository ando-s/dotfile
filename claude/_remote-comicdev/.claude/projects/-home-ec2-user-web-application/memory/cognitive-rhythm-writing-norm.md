日本語の説明文（設計ドキュメント、仕様書の地の文、記事）を書く・推敲するときは、`japanese-tech-writing` スキルに加えて「認知リズムを生むための日本語ライティング規範」を参照する。

出典: https://gist.github.com/k16shikano/eb2929f13ed19c97188393d297be8432
（raw: `https://gist.githubusercontent.com/k16shikano/eb2929f13ed19c97188393d297be8432/raw`）

**Why:** 2026-08-07 にユーザーから「認知リズムを参考にしてね」と指示された。密度の高い技術文書が読み進められなくなるのは情報量ではなく、全文が同じ認知モードで書かれているため。

**How to apply:**

- **話題テスト**（最重要）: その文が更新するのは「状況」か「文書」か。文書更新（進行実況・議題表・節末予告・本文の性格宣言）は原則削除。短く断定調にすると駄文が生き残るので、短さとリズムの良さを残す理由にしない
- **拍**: 短文で立てる → 長文で流す → 短文で止める。長い断定が 3 つ以上続いたら短文か逡巡を挟む
- **緊張**: 素朴な期待が事実に破られる形を作る（「電文は 4 つある。うち 3 つは Nuts が送る。会員登録の電文だけは送らない」）。説明文では対象そのものの性質から取り、本文の進行を語って代用しない
- **装置は宣言せず内容で実現**: 「先に答えを半分だけ置く」のような操作の宣言自体が駄文
- **節の入り方**: 「本節では〜を扱う」で始めない。違和感の言い直し・読者の反問・書き手の告白のいずれかで入る
- 例外的に残してよい文書更新は 4 形のみ: 具体的に引用した誤読の反論処理、問いの設置と回収、境界での読者への依頼、架空例の枠の開閉
