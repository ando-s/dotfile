返信文・コミットメッセージ・コメント・回答本文等、人が読む出力は平易な事実語で書く。CLAUDE.md「誰が見ても分かる言葉を使う」「事実を淡々と書く」に従う。

**判定基準（語ごとに自問する）:** その語の意味が、文字どおりの事実でなく次のいずれかに依存していたら言い換える。

- イメージ・比喩に依存（戦・移動・身体などの例え）
- 勢い・程度の強調に依存（深刻さを煽る）
- チーム内の共有文脈に依存（外部の人は別の意味に取りうる）
- 実在する対象を、その場で作った一般名詞で言い換えている（読み手が現物に辿り着けない）

言い換え方: その語が指している事実（対象・条件・方向・挙動・件数）に置き換える。**実在するテーブル・モデル・クラスを指すなら、実際の名前をそのまま書く。**

**例（基準の当てはめ。網羅リストではない）:**

- 「緑（のまま）」= 共有文脈依存 → 「テストが失敗せず見逃される」
- 「本丸」= 比喩依存 → 「移行の主目的＝Nutsが決済を処理すること」
- 「逆走」= 比喩依存 → 「移行方針と反対方向」
- 「致命的」「ハマる」「難所」= 程度の強調 → 起きる事象と条件を書く
- 「Spica口座」「会員口座」= その場で作った一般名詞 → `UserSonyPaymentAccount` とモデル名で書く
- 「直読み」= 様態の強調（かつ事実と違う。実際は Reader 経由） → 「`UserSonyPaymentAccount` を読む」と書く
- 「no-op」= 英語の略語（読み手が意味を取れない） → 「何もせずに戻る」「列を変えずに終わる」と挙動を書く
- 「バックフィル」= 英語ジャーゴン → 「既存の行をまとめて更新する」と書く

**記号で言い換えをつながない:** 本文中で「A＝B」のように＝で語を言い換えると読みづらい。ふつうの文で書く。

**Why:** MR16370 のコミットで「テストが緑のまま」と書き伝わらないと指摘。別セッションで判断説明に「本丸」「逆走」を使い再指摘。禁止語リスト方式は載っていない語を取りこぼすため、語の性質で判定する基準を一段挟む。

**How to apply:** 出力前に、勢い・例え・色・略語が混じった語を見つけたら基準に当て、指している事実へ置き換える。[[minimalism-not-skip-tests]]
