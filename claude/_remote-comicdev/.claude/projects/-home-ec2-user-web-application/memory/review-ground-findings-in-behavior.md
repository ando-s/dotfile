コードレビューで指摘・[ask] を出すときは、**具体的な失敗経路（どの入力・順序で問題が起きるか）で裏付ける**。一般論（「非冪等だから」「念のため」）だけで意図確認を投げない。

判定基準：
- 既存の動いている実装のコピーで、挙動が同じなら、それ自体は指摘しない
- 「2回呼ばれたら」等を疑うなら、**実際に二重呼び出しが起きる経路があるか**を先に確認する（ガード・状態遷移で防がれていないか）
- 挙動が問題なければ指摘しない。失敗経路を示せる時だけ出す

**Why:** MR16383 レビューで `already_unregistered → 400` を「非冪等」と反射で [ask] にしたが、`active_shift_course?` ガードで再呼び出しは起きず、既存 unregister と同挙動だった。失敗経路の裏付けが無い指摘だった。

**How to apply:** 指摘を書く前に「この問題が起きる具体的な入力・順序は？それは既存のガードで防がれていないか？」を自問する。答えられないなら出さない。[[minimalism-not-skip-tests]]
