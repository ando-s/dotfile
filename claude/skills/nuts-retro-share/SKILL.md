# Nuts振り返り共有の下書き

振り返り共有MTの議事録に、次回分の節の下書きを作る。MTの目的は「Nutsの進捗に問題がないか、問題があるなら根本解決できているか」を内田さんと確認すること。

## ⚠️ 守ること

- **議事録ドキュメントには書き込まない。** 下書きはチャットに出し、貼り付けはユーザーが行う。読み取りだけを行う
- ガントチャートの書き換え・JIRA の更新は、このスキルの範囲外。必要に見えたら提案だけする

ドキュメントは Google ドライブのコネクタの `read_file_content` で読む。

ガントチャートの描画シートは名前が日時（例 `2026-09-15 12:55:17`）で、作り直すと変わる。スプレッドシートのコネクタの `get_spreadsheet`（`fields` は `sheets.properties.title`）でシート名を一覧し、`設定`・`プロジェクト`・`休業日`・`【old】…`・`…_更新履歴` と、`_` で始まる保存用のシート（`_計画`・`_方針`・`_メモ`・`_メモ_履歴`・`_休日`）以外のシートを描画シートとして読む。描画シートの名前は今は固定（`ガント：タスク単位`・`ガント：エピック`・`ガント：マイルストーン`）。値は `get_values` で読む。

描画シートの読み方。

- 3〜5行目を `A3:BZ5` で取り、3行目の日付と5行目「スプリントの方針」を列で対応させる。方針は週の初日の列に入っている
- タスク行は `A6:H200`。1つのチケットに `計画(M/D)` の行が複数あり、日付が最も新しい行が今の計画。前の版との差が期日の変更になる

## 手順

### 1. 対象の週を決める

- 議事録の先頭の節（最新の `## YYYY/MM/DD`）を見る
- 先頭の節の「やったこと」に結果（=> 完了 など）が付き「来スプリント」も埋まっていれば、次の週の節を作る。前回の予定を写しただけで結果が無い、または「来スプリント」が空なら、先頭の節を対象にする
- 期間は前回の期間の翌日から MT 当日（前日）まで。前回の節の書き方に合わせる

### 2. 材料を集める

並行して読む。

- **議事録**: 対象の1つ前の節の「来スプリント やること」。今回の「やったこと」の骨組みになる
- **チームの振り返り**: 対象期間に当たる日付の節の moyamoya・try。空の節は使わない
- **ガントチャート描画シート**: 5行目付近の「スプリントの方針」行のうち、対象の週の列。プロジェクト行の目標日・メモ列
- **`_メモ` シート**: チケットごとの遅延理由・判断
- **プランニング**: 対象期間と次の期間の節（休み・決めたこと）
- **JIRA**: 期間内に完了したもの・進行中のもの。対象プロジェクトはガントチャートの `プロジェクト` シートの PROJECT_KEY から取る

```
jira issue list -q 'project in (<KEYS>) AND (resolved >= "<期間開始>" OR statusCategory = "In Progress")' --plain --columns key,status,summary,assignee
```

### 3. 下書きを組み立てる

議事録の直近の節と同じ構成・書き方にする（見出しの階層・「=> 完了」の付け方・目標日の括弧書き）。2026-10 時点の構成は次のとおり。

```
## YYYY/MM/DD
期間：YYYY/MM/DD - YYYY/MM/DD
#### 今スプリント
やったこと
- <プロジェクト>（目標：MM/DD）
  - <作業> => 完了 / 着手 / レビュー前 など
#### 来スプリント
やること
- <プロジェクト>（目標：MM/DD）
  - <作業>（〜MM/DD、担当があれば名前）
### メモ
- 期日・目標の変更と理由
- 体制の変化（ジョイン・離任）
- 休み
```

組み立てのきまり。

- **「スプリントの方針」行を優先する。** プランニングのメモやチケットのメモと食い違ったら方針行に合わせ、食い違いは「確認してほしいところ」に書く
- 前回の「来スプリント」の各項目に、結果（完了・着手・未着手・延期）を付けて「やったこと」にする。予定になかった完了チケットは該当プロジェクトの下に足す
- 目標日が変わったら `（目標：旧 → 新）` と書き、理由をメモに書く
- 人名は過去の議事録の書き方に合わせる（「業務委託の方」ではなく名前）
- チケット番号・MR番号は本文に並べない。作業内容を日本語で書く
- 確認できなかった事柄（レビュー依頼を出せたか等）は書いた上で「確認してほしいところ」に挙げる

**大事なところに絞る。** MTの目的に照らし、残すのは次のものだけ。

- やったこと：プロジェクトごとに、目標日に効く作業の結果1〜2行
- やること：プロジェクトごとの次の山場と期日。優先度が決まっていれば最優先のプロジェクトを先頭に書く
- メモ：目標日の変更と、その理由・見積もりの前提

外すもの。

- 進行中の細かい作業（設計の着手、ドキュメント更新など目標日に効かないもの）
- 振り返りで出た個人の話。遅れの理由として方針行やメモに書かれていれば、その理由として1行で書く
- 退任者の後片付け・休み・改善チケットなど、進捗の判断に関わらないもの

チケットの終了予定を過ぎて未完了のものは、本文に書かず「確認してほしいところ」で、目標を守れそうかを MT で確かめる論点として挙げる。

### 4. 出力

チャットに次の順で出す。

1. 下書き本文（貼り付けられる形、絞った版）
2. **外したもの**: 絞るときに落とした項目を1行ずつ。ユーザーが戻せるようにする
3. **確認してほしいところ**: 期日を過ぎたもの・資料間の食い違いと採用した側・未確認の事柄

全部入りの版を求められたら、外したものも本文に戻して出す。

ガントチャートが更新されたと言われたら、2 から読み直して作り直す。

## MTの後

MTで分かったこと（議事録のメモに追記された内容）を JIRA チケットに反映したいと言われたら、メモの該当箇所を抜き出し、追記する文面を全文示して承認を得てから更新する。
