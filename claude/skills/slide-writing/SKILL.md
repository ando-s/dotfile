# slide-writing（登壇スライドの文言）

本人が登壇で使うスライドの文言を書くときの規範。装飾やAPI操作ではなく、**何を書くか・どう削るか**を扱う。
全社共通の文章規範（誇張語を使わない、造語を使わない等）はグローバル CLAUDE.md に従い、ここではスライド特有の点だけを持つ。

## 原則

1. **1枚1メッセージ。** 同じことを別の言い方で2箇所に書かない。帯と脚注で内容が重なったら、片方を別の軸（範囲／量／時間など）に振り直すか消す。
2. **項目は項目のまま書く。** 自己紹介や所属のような列挙は「〜しています」と文にしない。「決済分離プロジェクト、PM」のように名詞で止める。
3. **ラベルを足さない。** 「自己紹介」のような、見ればわかる見出しは置かない。
4. **主観のコストを混ぜない。** 「精神的コスト」「負担」のような感覚語ではなく、事実（見る範囲・件数・時間）で書く。
5. **因果は1段だけ。** 「AがBになってCが遅れる」と3段にせず、「AIによってコード生成が増え、レビューが追いつかない」で止める。読み手が1段先を補える。
6. **根拠のない比較級を書かない。** 「〜ほど効く」は比較対象と観測が両方ないと書けない。手元の事実で言えることに置き換える。
7. **聴衆の得るものを先に置く。** 社内の計測報告をそのまま出さない。意外な観測（例: 直すほど指摘が増える）を先に出し、数字は裏付けとして添える。

## レイアウトに関する既定

- 人物アイコンなどの図は左、説明は右。
- アイコンの下に名前・所属のキャプション（13pt グレー・中央寄せ）。

## デザインを揃えるときの手順

既存のスライドに後半・別ページを合わせるとき。

1. **先に markdown（台本）を直し、スライド編集はその後。** markdown を正本にし、スライドとスピーカーノートは markdown から更新する。編集後に3つの整合を確認して報告する。
2. **揃える対象はフォントと位置だけではない。** 背景色の使い分け、バッジ・カードの有無と形、ページ構成（見出し位置・余白）を先に前半から読み取り、一覧にする。
3. **編集前に「どのスライドを何に合わせるか」を一覧で出して承認を取る。** 承認前にスライドを触らない。
4. **表は行数を絞り、文字を大きくする。** 情報を詰めるより枚数を分ける。
5. **画像は API で挿入できない。** 手動手順を最後にまとめて出す。
6. **依頼されていない出力を作らない。** PDF 書き出し、題名候補の量産などは、求められたときだけ。

## 指摘ログ

ユーザーから文言の指摘を受けたら、ここに1行で足す。原則に昇格できるものは上の節へ移す。

- 2026-09-11 「精神的コストは別に」→ 感覚語を落とし、範囲と時間の事実だけにした
- 2026-09-11 「AIによってコード生成が増えた、じゃない？」→ 速度ではなく量で書く
- 2026-09-11 「マージが遅れるは冗長」→ 因果の3段目を削る
- 2026-09-11 「自己紹介というラベルもいらない」→ 自明な見出しを置かない
- 2026-09-11 「決済分離プロジェクト、PM という項目感でいいです」→ 列挙は文にしない
- 2026-09-11 「画像を左で説明は右」→ 図は左、説明は右
- 2026-09-11 「『埋める穴がはっきりしているほど効く』の根拠がよくわからない」→ 観測のない比較級を消す
- 2026-09-11 「正直聴衆側に撮っては面白くない」→ 内部の計測報告を並べず、聴衆の持ち帰りから組む
- 2026-09-12 帯と脚注が同じ話になっていた → 帯は範囲、脚注は量、と軸を分けた
- 2026-09-14 「1行入れる話だけど、口頭で補足するってのも選択肢にある」→ 情報を足すとき、スライドに書く／口頭だけで言う、を毎回選ぶ
