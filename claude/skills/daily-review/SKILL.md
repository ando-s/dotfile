# daily-review（Claude Code 自己振り返り）

前回レビュー以降の全プロジェクトの会話履歴を分析し、自分(Claude)の使われ方から
改善余地を抽出してレポート化する。ユーザーは毎朝これを読んで Claude を「育てる」。

## 手順

### 1. ダイジェストを生成する

会話履歴の生 jsonl は巨大なので、抽出スクリプトで圧縮したダイジェストを作る。

```bash
python3 "${CLAUDE_SKILL_DIR}/scripts/extract_conversations.py"
```

`--since` が `$ARGUMENTS` で渡されていればそれを付ける。未指定なら直近レポートの
タイムスタンプ、それも無ければ24時間前が基準になる。
出力された `digest_path=` のパスを控える。

### 2. ダイジェストを読む

`digest_path`（既定 `~/.claude/daily-review/digest.md`）を Read する。
対象が0件なら「前回以降の活動なし」とだけ報告して終了。

### 3. 4観点で分析する

ダイジェストの「ユーザーの指示」「bash コマンド」「ツール使用」から、以下を抽出する。
**根拠は必ずダイジェスト内の具体的な指示・コマンドを引用する**。一般論で埋めない。

1. **スキル化候補**: 複数セッション/複数回にわたり繰り返された定型タスク。
   手順が固定化していて毎回同じ指示を出しているもの。提案するスキル名・トリガー・概略手順を書く。
2. **サブエージェント化候補**: 長い探索・調査・並行作業で、メインの文脈を汚さず
   隔離した方がよかったもの。どの作業を、どんな agent 定義で切り出すか。
3. **CLAUDE.md / agents.md 改善候補**: 同じ前提説明・同じ訂正を繰り返している箇所。
   ルール化すれば毎回の往復が減るもの。追記すべき具体的な一文を示す。
4. **settings.json permissions 追加候補**: 頻出する bash コマンド（先頭トークン頻度を参照）で、
   許可リストに入れれば承認プロンプトを減らせるもの。`Bash(cmd:*)` 形式で具体的に書く。
   破壊的コマンド（rm/git push等）は安易に勧めず注意を添える。

各観点で候補が無ければ「該当なし」と明記する（無理に絞り出さない）。

### 4. レポートを書き出す

ファイル名は実行時刻で決める:

```bash
mkdir -p ~/.claude/daily-review/reports
echo "report_path=$HOME/.claude/daily-review/reports/review_$(date +%Y%m%d_%H%M%S).md"
```

このパスに Write する。次回の `--since` 基準になるので **必ずこの命名で書く**。

## レポートのフォーマット

```markdown
# Claude Code 振り返りレポート（YYYY-MM-DD HH:MM）

- 対象期間: <since> 〜 <now>
- 対象セッション: <件数>

## 🟢 サマリ
<2〜4行。今回の活動の傾向と、最も効果が高い改善1つ>

## 🔧 スキル化候補
- **<スキル名案>**: <根拠の指示/コマンドを引用> → <提案するトリガーと手順>

## 🤖 サブエージェント化候補
- <作業> → <切り出す agent の役割と理由>

## 📝 CLAUDE.md / agents.md 改善候補
- <繰り返している前提/訂正> → <追記すべき一文>

## 🔑 settings.json permissions 追加候補
- `Bash(<cmd>:*)` — <頻度と根拠>（⚠️ 破壊的なら注意書き）

## 補足
<未確定事項・判断に迷った点>
```

## 注意

- **提案のみ**。スキル作成・settings.json編集・CLAUDE.md編集は **このスキルでは行わない**。
  ユーザーがレポートを見て採否を決める。勝手に実装しない。
- 根拠の無い提案を書かない。ダイジェストに現れた事実だけを根拠にする。
