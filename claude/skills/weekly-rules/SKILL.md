# weekly-rules（週次の、指摘から規則を作る）

ユーザーが Claude を直した場面から、次から直さなくて済むための規則を作る。
規則を書き込むかは毎回ユーザーが決める。Claude が勝手に書き込まない。

## 1. 材料を集める

```bash
python3 -I "${CLAUDE_SKILL_DIR}/scripts/extract_corrections.py"
```

`$ARGUMENTS` に `--days N` があれば付ける。出力の `pairs_path=` のファイルを読む。
ユーザーの発言と、その直前の Claude の発言が対になっている。このスキル自身のセッションは除かれている。

`pairs=0` なら「前回以降の会話なし」とだけ返して終える。

## 2. 直した場面を拾って分ける

材料は1週間で数百KBになる。メインの会話で読まず、Agent（general-purpose）に読ませる。
Agent には、材料のパス、下の拾い方と分け方、出力先 `~/.claude/weekly-rules/corrections_<日付>.md` を渡し、
「直した場面の一覧（日付・ユーザーの発言・直前の Claude の発言・種類）と、種類ごとの件数」を書かせる。
メインの会話では、その出力だけを読む。

ユーザーの発言のうち、Claude のしたことや書いたことを直したもの・止めたもの・やり直させたものだけを拾う。
新しい依頼、「ok」などの承認、質問は拾わない。

拾った場面を、種類ごとにまとめる。種類は材料から決め、例に引きずられない。例:

- 調べ方が浅いまま案を出した
- 頼んでいないこと・聞かれただけのことを実行した
- 書く先・対象を間違えた
- 文章の言い回し・構成（人に読ませる文章）
- ローカルと comicdev の片方にだけ反映した
- 権限やツールの拒否のあと、別の手段に切り替えた

## 3. 今の規則と照らし合わせる

種類ごとに、次のどれに当たるかを確かめる。確かめた場所を書く。

- `~/.claude/CLAUDE.md`（正本は `~/dev/dotfile/claude/CLAUDE.md`）
- `~/dev/dotfile/claude/skills/` の各スキル（文章は `writing-for-others`）
- 作業したフォルダ・リポジトリの CLAUDE.md（自動メモリはオフにしているので、メモリには置かない）

| 分け方 | 扱い |
|---|---|
| 規則が無い | 2回以上出ていれば、規則の案を作る |
| 規則はあるのに守れなかった | 規則を増やさない。「守れなかった」として件数と場面を報告する。書き方が分かりにくいせいなら、書き直しの案を出す |
| 文章の指摘 | `writing-for-others` の指摘ログに足す案にする |
| わかりにくいと言われた語 | 1回でも、`~/dev/dotfile/claude/docs/使わない語.md` に代わりの書き方と一緒に足す案にする |
| 規則を足したのに、同じ種類の指摘が続いている | 規則の書き方ではなく仕組み（質問の形、確かめる手順、機械での確認）を変える案を出す |

1回だけの指摘は、案にせず「1回だけのもの」として一覧に残す。

## 4. 案を見せて、1つずつ決める

最初に、全体を短く返す: 拾った場面の数、種類ごとの件数、案の数、守れなかった規則の数。

そのあと、案を1つずつ AskUserQuestion で聞く。1問に1案。各案には次を付ける。

- 規則の文面（そのまま貼れる形）
- 置き場所（ファイルと節）
- 根拠（ユーザーの発言の引用と日付を2つまで）

選択肢は「この文面で足す」「直してから足す」「足さない」。

## 5. 採った案を書き込む

- 採った案だけを書き込む。dotfile は main に直接コミットする。push はユーザーが頼んだときだけ。
- チームのリポジトリ（会社の GitLab のグループのもの）に置く案は、直接書かず MR にする。
- 最後に、実行した日時を記録する。

```bash
date -u +%Y-%m-%dT%H:%M:%SZ > ~/.claude/weekly-rules/last-run
```

## 守ること

- 材料（`~/.claude/weekly-rules/`）には社内の発言が入る。dotfile や Obsidian に写さない。
- 規則は、根拠の場面で何をすればよかったかが分かる形で書く。「気をつける」「注意する」で終えない。
- 文章はグローバル CLAUDE.md の書き方に従う。
