# 仕事研究

勤務先の仕事を勉強のために調べ、1テーマ＝1つの Google ドキュメント（タブ付き）にまとめる。目的は2つある。

- 仕事の中身を知る
- 課題にどう取り組むかを、自分で考える練習をする。課題のタブには事実だけを書き、「自分の考え」の欄は空けておく

## 守ること

- **社内の資料は、読む前に一覧で承認を取る。** Drive・Slack・Chat・JIRA・GitLab などの本文を読む前に、「読みたい資料の名前・場所・読む理由」を一覧で示し、承認された分だけ読む。一覧を作るための名前の検索（ファイル名・チャンネル名・件名）はしてよい
- **Obsidian の私用 vault（armond）に社内の情報を書かない。** 同期されるため。成果物は Google ドライブに置く。ローカルの下書きは作業用の一時フォルダに置き、終わったら消す
- 資料で確かめられないことは「未確認」と書く。推測で埋めない
- 資料の時点（日付）を「はじめに」に書く

## 置き場所

- マイドライブの「03_仕事研究」フォルダの下に、テーマごとのフォルダを作る。フォルダは名前で探す（ドライブの `search_files` で `title = '03_仕事研究' and mimeType = 'application/vnd.google-apps.folder'`）
- テーマのフォルダには、ドキュメントを1つだけ置く。図などのファイルは、同じフォルダの「図」に置く
- 既存のテーマを更新するときは、同じドキュメントのタブを書き直す。URL を変えない

## 進め方

1. **テーマを決める**：誰の・何の仕事か、何を知りたいか（仕事の流れ、課題、設計、お金や契約など）を聞く。漠然としていてよい
2. **資料の候補を洗い出す**：名前の検索で候補を集め、一覧にして承認を取る
3. **読む**：承認された資料だけを読む。新しく読みたい資料が出てきたら、また一覧で承認を取る
4. **構成を決める**：下の「タブの構成」を基本にする。テーマに合わせて増減してよい
5. **下書きを書く**：タブごとに Markdown を作業用の一時フォルダに書く
6. **ドキュメントを作る**：下の「作り方」で、1つのドキュメントにタブを作って流し込む
7. **渡す**：ドキュメントの URL と、未確認のこと・承認がほしい次の資料を伝える

## タブの構成

| タブ | 中身 |
| --- | --- |
| はじめに | このドキュメントの目的、資料の時点、取り組みの概要、動いている案件と状況、関わる人と役割、仕事の流れ、用語、資料のリンク |
| 課題一覧 | 課題を案件ごとの表に。列は「課題・困っている人・分かっている数値・状態」。状態は「未着手 / 対応中 / 完了 / 不要」 |
| 課題（親タブ） | 子タブへのリンクの一覧だけ |
| 課題の子タブ | 1課題＝1タブ。下の「課題のタブの書き方」の形 |
| 設計（親タブ） | 子タブへのリンクの一覧だけ |
| 設計の子タブ | 1システム＝1タブ。目的・利用者・処理の流れ・構成・配布や運用・分かっている制約・未確認 |

### 課題のタブの書き方

前半は資料から分かる事実、後半は空欄にする。

```
状態：未着手 / 対応中 / 完了 / 不要

## 経緯
## 課題
- 誰が：
- どこで：
- どのくらいの頻度で：
- 数値：なければ「取りたい数値」を書く
## 理想の状態
## 分かっていること
## 分かっていないこと
## 出ている案（誰が出したかも書く）
## 出典

---

## 自分の考え
### 課題を自分の言葉で言い切る
### 前例と相談相手
### 選択肢
- 制約がなければ何をするか：
- 今あるものだけで何ができるか：
- 他社や社内の別チームはどうしているか：
### 決める人と、渡すもの
### 最初の一歩
```

## 作り方

Google ドキュメントのタブは、Markdown や HTML の取り込みでは作れない。Google のコネクタでドキュメントとタブを作り、`scripts/md2tab.py` が作る要求で書式付きの本文を流し込む。Google ファイルを作る前に `anthropic-skills:google-workspace` スキルを読む。

1. テーマのフォルダに空のドキュメントを作る（ドライブの `create_file`、`contentMimeType` は `application/vnd.google-apps.document`、`parentId` はテーマのフォルダ）
2. タブを作る（ドキュメントの `update_doc`）
   - 最初のタブは `t.0`。`updateDocumentTabProperties` で名前を付ける
   - 2つ目からは `addDocumentTab`。子タブは `tabProperties.parentTabId` に親の tabId を入れる
   - 返ってきた tabId を控える
3. タブ同士のリンクは `https://docs.google.com/document/d/<documentId>/edit?tab=<tabId>` の形にする。タブを先に全部作ってから、本文の中のリンクを書く
4. 各タブの要求を作り、出力の JSON 配列をそのまま `update_doc` の `requests` に渡す。要求は空のタブを前提にする

```bash
python3 -I ~/.claude/skills/work-research/scripts/md2tab.py <tabId> <下書き.md>
# 既存のタブを書き直すとき。タブの本文の最後の要素の endIndex を read_doc で読んで渡す
python3 -I ~/.claude/skills/work-research/scripts/md2tab.py <tabId> <下書き.md> --clear-end <endIndex>
```

- 対応している書式：見出し（#〜######）、箇条書き（入れ子は2文字の字下げ）、番号付きの箇条書き、表、太字、リンク、インラインコード、コードブロック
- 表の前には空の段落が1つ入る
- 画像は埋め込めない。画像は「図」フォルダに置き、本文からは Drive のファイルへのリンクにする
- 要求にはページ分けなしの設定も入っている
- `read_doc` は文書全体の構造を返すので大きい。読むのは書き直しの endIndex を取るときと、最後に `documentStyle.documentFormat.documentMode` が `PAGELESS` か確かめるときだけにする

## 文章

- 結論を先に、平易な日本語で書く。誇張語・比喩・内輪の言葉を使わない
- 人名は役割と一緒に書く。所属が分からない人は「所属は未確認」と書く
- 数値・日付・金額は資料のとおりに書き、出典の資料名を添える
